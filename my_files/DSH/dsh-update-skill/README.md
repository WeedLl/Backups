# dsh-update — скилл обновления DSH без потери плагинов и скиллов

Скилл для агента DSH: проверяет обновления ядра, TUI и плагинов всех профилей,
оценивает риски, делает проверяемый снимок, устанавливает выбранное и проверяет,
что после обновления живы все плагины и скиллы — включая локальные форки.

## Зачем

Обновление DSH трогает три независимых слоя: глобальное ядро (npm), TUI внутри
профиля (pnpm) и плагины каждого профиля. Они обновляются по отдельности и легко
расходятся: ядро новее, чем поддерживает TUI; `file:`-форк заменён версией из
npm; пакет из npm перекрыл ваш локальный скилл; `dsh_backup` молча перестал
копировать новые файлы.

Скилл закрывает именно это: проверка совместимости до установки, снимок с
самопроверкой до и откат после, живая проверка загрузки плагинов после.

## Установка

```bash
# из каталога, где лежит этот README
./scripts/install.sh          # симлинк: правки видны сразу
./scripts/install.sh --copy   # независимая копия

# на другую машину: скопировать каталог целиком и запустить install.sh
```

Скилл станет доступен как `/dsh-update` в следующей сессии DSH.

## Быстрый старт

```bash
/dsh-update            # отчёт: что устарело и чем грозит
/dsh-update verify     # проверить текущее состояние
/dsh-update update     # обновить (со снимком и проверкой)
/dsh-update rollback   # откатить
```

Из терминала:

```bash
scripts/selftest.sh                 # живы ли допущения скилла
scripts/check.sh                    # отчёт об обновлениях
scripts/check.sh --json             # то же машинно
scripts/snapshot.sh create --label pre-update
scripts/apply.sh --tui 0.20.1 --yes
scripts/verify.sh --all --smoke
scripts/rollback.sh --yes
scripts/doc.sh path                  # куда пишется журнал версий
scripts/doc.sh write --stdout        # посмотреть журнал, не записывая
```

## Что внутри

| Файл | Назначение |
|---|---|
| `SKILL.md` | инструкция агенту: режимы, правила, порядок шагов |
| `scripts/selftest.sh` | проверка, что скрипты ещё соответствуют этой версии DSH |
| `scripts/check.sh` / `check.mjs` | отчёт об обновлениях, риски, матрица совместимости |
| `scripts/snapshot.sh` | снимок конфигов/скиллов/состояния TUI + самопроверка |
| `scripts/apply.sh` | установка: официальный апдейтер или точные версии |
| `scripts/verify.sh` | пост-проверка: конфиги, bundles, lockfile, скиллы, smoke |
| `scripts/rollback.sh` | откат файлов, опционально зависимостей и ядра |
| `scripts/doc.sh` / `doc.mjs` | журнал версий `dsh-versions.md` для Obsidian |
| `scripts/install.sh` | установка скилла в `~/.dsh/skills` |
| `scripts/collect.mjs` | сбор фактов о профилях в JSON |
| `scripts/util.mjs` | semver, peer-диапазоны, pnpm-lock, фронтматтер скиллов |
| `references/` | каталог рисков и рецепты восстановления |

## Как это устроено

1. **selftest** — сверяет команды и пути, на которые опираются скрипты.
2. **check** — читает реестр npm, `pnpm outdated` в каждом профиле, peer-диапазон
   TUI, локальные `file:`-зависимости, покрытие `dsh_backup`. Ничего не меняет.
3. **snapshot** — копирует конфиги профилей, домашний слой, скиллы и состояние
   TUI; пишет манифест с версиями и baseline предупреждений загрузчика; считает
   контрольные суммы и проверяет восстановление в temp-каталог.
4. **apply** — TUI → ядро → плагины, с проверкой фактически установленной версии
   после каждого шага. При провале — стоп и команда отката.
5. **verify** — статические проверки + опционально живые: web (HTTP + активация
   плагинов), tui (boot в PTY), headless (короткий прогон).
6. **doc** — после обновления переписывает `dsh-versions.md`: версии до/после,
   предыдущее обновление, история, проверка и снимок.

## Где лежат данные

```
~/.dsh/updates/snapshots/<дата>-<метка>/   снимки конфигов, скиллов и состояния TUI
~/.dsh/updates/reports/verify-<дата>/      отчёты проверок (current.json, smoke-*.out)
~/.dsh/updates/snapshots/.latest           указатель на последний снимок
~/.dsh/updates/doc-target                  выбранный fallback для журнала
```

Хранятся последние **5 снимков** и **20 отчётов**; более старые удаляются
автоматически при создании снимка и после успешного обновления. Снимок из
`.latest` не удаляется никогда — это точка отката. Лимиты меняются переменными
`DSH_UPDATE_KEEP_SNAPSHOTS` и `DSH_UPDATE_KEEP_REPORTS`, ручная очистка —
`scripts/snapshot.sh prune [--keep N] [--keep-reports M] [--dry-run]`.

## Журнал версий

После обновления скилл пишет `dsh-versions.md` — Obsidian-заметку с `type: backup`:
ядро, TUI и все плагины по профилям, «до → после» текущего и предыдущего
обновления, история, проверка и снимок. По умолчанию —
`~/Documents/ForSys/Backup/doc/`; если `doc/` нет, скилл спрашивает `Backup/`
или `answers/` и запоминает выбор. Рядом лежит скрытый `.dsh-versions.json` с
историей. Ошибка записи журнала не отменяет обновление.

## Требования

- Linux/macOS, bash, node ≥ 18
- `dsh` в PATH, `npm`/`pnpm` для установки
- `sha256sum` или `shasum`, `curl`; `script` — для smoke-теста TUI

## Разработка

```bash
scripts/selftest.sh                 # после правок
node --check scripts/*.mjs          # синтаксис
bash -n scripts/*.sh
node scripts/check.mjs --offline    # без сети
```

Скилл намеренно не имеет зависимостей: только node stdlib и системные утилиты.
Так он переживает обновления DSH и не ломается вместе с `node_modules`.

## Ограничения

- Не перезапускает сессию: после обновления нужен ручной рестарт TUI/web.
- `verify --smoke` поднимает второй экземпляр приложения.
- Живой headless-прогон требует `DEEPSEEK_API_KEY` в окружении.
- Локальные форки не обновляются автоматически — только диагностика и
  переустановка по просьбе.
- Журнал версий пишется best-effort и не содержит секретов.
