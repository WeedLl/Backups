# Каталог рисков обновления DSH

## 1. Версии и теги

- **`latest` ≠ самая новая.** У `@deepseek-ai/dsh` есть `latest`, `next`, `alpha`.
  `npm i -g @deepseek-ai/dsh@latest` может оставить вас на старой версии, пока в
  `next` лежит более новый rc. И наоборот: установка `next` без проверки TUI
  ломает совместимость.
- **rc-версии сравниваются лексикографически по номерам.** `0.2.2-rc.5` новее
  `0.2.2-rc.1`; `0.2.2-rc.10` новее `rc.9`. `util.mjs cmp` учитывает это.
- **`0.x` — особый случай.** Для пакетов < 1.0.0 минорный апгрейд (`0.78 → 0.85`)
  считается ломающим.

## 2. Совместимость TUI ↔ ядро

`@deepseek-harness-tui/dsh-tui` объявляет поддерживаемые версии ядра в
`peerDependencies["@deepseek-ai/dsh-agent"]` — длинным списком точных версий и
`^`-диапазонов. Проверка:

```bash
node scripts/util.mjs peer "<range>" "<core-version>"   # yes | no | unknown
```

Если вердикт `no` — комбинация не поддерживается, даже если обе части «свежие».
Обновлять такую пару можно только одновременно и только если новый TUI заявляет
новое ядро.

Отдельно: адаптер `dst` (headless-режим TUI) имеет **свой** узкий список
валидированных версий и может отказать там, где сам TUI работает
(`ADAPTER_UNAVAILABLE`). Это не поломка обновления, а ограничение адаптера.

## 3. Порядок обновления

Правильный порядок: **TUI → ядро → плагины**.

- если упадёт установка TUI, остаётся рабочая пара «старый TUI + старое ядро»;
- если сначала обновить ядро, можно остаться с новым ядром и старым TUI, который
  его не поддерживает;
- плагины ставятся последними: их зависимости разрешаются против уже
  обновлённого дерева.

## 4. Локальные `file:`-зависимости

`dsh plugin add/update` пересобирает дерево pnpm. Для `file:`-пакетов это значит:

- пакет перелинковывается из исходника (содержимое исходника не меняется);
- если исходник переименован/удалён — пакет исчезает из профиля;
- если имя `file:`-пакета совпадает с именем в npm (`dsh-tui-pkg`) — установка
  `name@latest` **заменит форк** апстримом.

Проверка: `check.sh` показывает все `file:`-зависимости, их версии и наличие
исходника; `checks.mjs` предупреждает, если установленное имя пакета отличается
от имени зависимости (признак переименованного форка).

## 5. Правки внутри пакетов

Пакет из npm может содержать не только код, но и скилл (`dsh-fact-check/SKILL.md`).
Любая правка внутри `node_modules/<pkg>` исчезнет при следующем обновлении.

Правильно: форк отдельным каталогом + `file:`-зависимость, или отдельный
скилл в `~/.dsh/skills`.

## 6. `cordis.patch.yml`

Патчи адресуются по `id` и `name`. Новая версия ядра или плагина может
переименовать запись — патч молча перестанет применяться (иногда с
предупреждением `patch: entry "..." not found`).

Проверка: предупреждения `dsh --profile X --dump-config` сравниваются с базовой
линией снимка; новые предупреждения попадают в отчёт как `loader-warning`.

## 7. pnpm: release age и build scripts

- `minimumReleaseAge` (по умолчанию 24 часа) запрещает установку только что
  опубликованных версий. `/update` обходит это, дописывая
  `minimumReleaseAgeExclude` с точной версией. Скрипты этого скилла так не делают:
  при ошибке установки свежего релиза подождите сутки или обновитесь через
  `/update`/`apply.sh --official`.
- `allowBuilds`/`onlyBuiltDependencies`: pnpm ≥ 11 может отказать в установке
  (`ERR_PNPM_IGNORED_BUILDS`), если в дереве есть пакеты с build-скриптами.
  Официальный апдейтер TUI pre-seed'ит `false`-записи для своей цепочки; при
  ручной установке ошибка возможна — используйте `--official` или `/update`.

## 8. Скиллы

- Глобальные скиллы: `~/.dsh/skills/*/SKILL.md` — общие для всех профилей.
- Скиллы плагинов: `<pkg>/SKILL.md` или `<pkg>/skills/*/SKILL.md` внутри
  `node_modules` — принадлежат версии пакета и меняются вместе с ней.
- Одинаковое имя скилла: пользовательский скилл перекрывает плагинный; два
  плагинных в одном профиле — неопределённость.

Проверка фронтматтера: `name` в kebab-case, `description` непустой, YAML между
`---`.

## 9. `dsh_backup` (zsh)

Бэкап работает по жёстким спискам: 5 файлов на профиль, фиксированный список
файлов `~/.dsh-tui`, `settings.yaml` и `cordis.patch.yml` домашнего слоя.
Скиллы `~/.dsh/skills` копируются, если в вашей версии функции есть блок
`skills/` — `check.sh` определяет это по тексту скрипта. Без него не покрыты:

- `~/.dsh/skills` (ваши скиллы),
- `~/.dsh/storages`, `~/.dsh/dsh-market`,
- `.credentials.yaml` (только с `-s`),
- новые файлы состояния, появившиеся после обновления TUI.

`check.sh` и `verify.sh` показывают расхождение и готовую строку
`tui_files+=(...)` для патча.

## 10. Права и окружение

- Любой запуск профиля перезаписывает `cordis.yml` → нужен доступ на запись в
  `~/.dsh`. В песочнице — `EPERM`.
- Живой прогон требует ключ модели в окружении (`DEEPSEEK_API_KEY`); иначе
  smoke помечается `skip`.
- Обновление ядра меняет файлы, но не текущий процесс: сессия продолжает работать
  на старом коде до перезапуска.

## 11. Тихие поломки

Плагин может «не активироваться», а приложение — стартовать с предупреждением.
Пример: `dsh-at-file` с `SyntaxError: ... does not provide an export named
'settingsNamespace'` — web поднимается, но плагин мёртв.

`--dump-config` такое **не ловит**: он собирает дерево, но не импортирует модули.
Ловит только живой запуск → `verify.sh --smoke`.
